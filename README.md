# 🇩🇪 German Citizenship Test (Einbürgerungstest)

All **300 general + 160 state-specific** questions from the official **BAMF Einbürgerungstest / Leben in Deutschland** test catalog — free, with correct answers highlighted ✅ and explanations, in **8 languages**.

Based on the official BAMF catalog (Stand: 07.05.2025).

> ⚠️ **Important:** For educational purposes only. Questions about current officeholders (Chancellor, Minister-Presidents) change with elections — always verify on the [BAMF website](https://www.bamf.de) before your test.

## 📂 About This Repository

The **`html`** branch is the only branch you need: it holds the markdown content, the build scripts and the built site that runs at [leben.wordfeather.com](https://leben.wordfeather.com/) (served by GitHub Pages).

**To read or browse the question content directly** (plain-text markdown with correct answers and explanations), open the source folders:

| Folder | Content |
|---|---|
| [`sources/english`](sources/english) | Questions + explanations in English |
| [`sources/urdu`](sources/urdu) | Questions + explanations in Urdu |
| [`sources/arabic`](sources/arabic) | Questions + explanations in Arabic |

German, Turkish, Russian, Persian, and Ukrainian content is kept as JSON dictionaries in the repository root (`de-explanations.json`, `tr-questions.json` / `tr-explanations.json`, `ru-questions.json` / `ru-explanations.json`, `fa-*.json`, `uk-*.json`) rather than as markdown.

## 🧱 How It's Built

A dependency-light static site: no framework, no server, no tracking. Content is data, pages are generated, and the whole site works offline.

```
sources/ (markdown) ─┐
*-questions.json     ├─► build.js ─► 192 static HTML pages, quiz-data.json,
*-explanations.json ─┘               search-index.json, sitemap.xml, sw.js
languages.js (registry of languages) ─┘
```

**Design choices**

| Decision | Why |
|---|---|
| **Static HTML, generated by one build script** (`build.js`, Node + `marked`) | Every question has its own indexable URL in every language, loads instantly and is served free by GitHub Pages. |
| **Language registry** (`languages.js`) | A language is one entry plus its translation files, not new code. Unfinished languages stay `enabled: false` and appear nowhere (no pages, no picker entry, no sitemap line). |
| **Content separated from code** | Markdown sources and JSON dictionaries hold the questions; templates and UI strings live in `build.js` / `strings.js`. |
| **Offline-first PWA** | `sw.template.js` is stamped with a content hash on every build, so users always get a consistent, fully cached version. |
| **Right-to-left support** | Urdu, Arabic and Persian are laid out RTL, with locally served fonts. |
| **Privacy** | Progress (learned questions, last scores, theme, language) is kept only in the browser's `localStorage`. There is no account and no analytics. |

**Quality checks** (run before every push)

```bash
npm run build            # regenerate everything; only changed pages are rewritten
node check-quiz-data.js  # question counts, missing translations, broken image references
node check-languages.js  # every enabled language is complete
```

**Notes on correctness.** The mock exam follows the real format (33 questions, 30 general + 3 of the chosen state, pass mark 17). State questions share the numbers 301–310 across all 16 states, so progress is stored per state (`<state>-<n>`) to keep states from overwriting each other.

> 💡 This site is the static companion of [WordFeather](https://wordfeather.com), a German vocabulary app with a Laravel API, accounts and a CEFR-aware learner model.

## 🛠️ For Developers

Edit the markdown under `sources/` (or the JSON dictionaries, `build.js`, `quiz.html`), then regenerate the site:

```bash
npm install
npm run build
```

`build.js` reads `sources/{english,urdu,arabic}` plus the `*-questions.json` / `*-explanations.json` dictionaries and writes the full static site: HTML pages for all 8 languages (192 pages), `quiz-data.json`, `search-index.json`, `sitemap.xml`, and a stamped `sw.js` service worker. Commit the result and push `html`; GitHub Pages deploys from there.

`check-quiz-data.js` runs a structural/content sanity check afterward (question counts, missing translations, broken image references, etc.) — worth running after any content change:

```bash
node check-quiz-data.js
```
